## Observed code and risks

- Real launcher hardcodes `SPORTS_HEDGE_MODE=real`, `SPORTS_HEDGE_EXECUTION_ENABLED=false`, `PAPER_AUTOFILL_ENABLED=false` and verifies disabled in /health. Simply changing an environment variable is overridden on startup.
- `application/paper_operations.py::_should_autofill` gates LIVE_PAPER automatic capture using the unfortunately paper-named `paper_autofill_enabled`; `capture_opening_fill` calls `_dispatch_live_opening` when `execution_armed` is true. Therefore REAL live canary requires an explicit, separately gated *opening trigger* AND execution arming. Never enable these two globally without bounded authorization.
- `execution/package.py` dispatches concurrent legs, `execution/dispatch.py` cancels a known Matchbook resting remainder, `execution/matchbook_http.py` notes unknown acknowledgements + after-restart duplicate-offer risk, `execution/polymarket_http.py` uses FAK buys and unknown/delayed outcomes. Existing orphan-recovery machinery cannot prove all unknown venue states. Must never retry ambiguously submitted orders.
- `execution/polymarket_preflight.py` and `execution/matchbook_preflight.py` have read-only account readiness checks. Polymarket current-IP `execution/polymarket_geoblock.py` fails closed. Native order minima may make £3/£5 total outlay infeasible for 2+ legs; do not evade platform minimums or silently increase operator budget.
- Current live diagnostics show PM degraded and sizeable Price-2 quote-skew errors; #42 and #43 must be accepted first, with integrated Linux/Windows test evidence and real populated native-token WS market data where feasible.
- The per-tranche and per-opportunity caps DO NOT constrain aggregate daily/session spend or multiple simultaneous opportunities. Add a **durable canary-specific session cap**, and reserve against pending/in-flight/unknown attempts before any submit to prevent racing duplicates.
